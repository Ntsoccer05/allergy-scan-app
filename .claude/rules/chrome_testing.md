# Chrome 実機テスト必須（ハーネス設計）

型チェック・ユニットテストだけでは検出できない「認証フロー・画面遷移・API通信・UI表示」のバグを防ぐため、
**UI 変更・API 変更・認証変更を含む実装はすべて Chrome 実機チェックをコミット前に必ず行う。**

MCP の `mcp__chrome-devtools__*` ツールを使用する。開発サーバーが起動済みであること（`http://localhost:3000`）。

---

## 実機チェック手順

### 1. ページ到達確認
```
mcp__chrome-devtools__navigate_page: http://localhost:3000
mcp__chrome-devtools__take_screenshot
```

### 2. 認証フロー検証（認証関連の変更時は必須）
- `/login` にアクセスしてログインフォームが表示されること
- メールアドレス + パスワードでログイン → `/scan` へ遷移すること
- クエリパラメータなし（`?redirect=` 等が URL に含まれないこと）
- 未ログイン状態で `/history` にアクセス → `/login` へリダイレクトされること

### 3. オンボーディングフロー検証（onboarding 変更時）
- Step1 → Step2（アレルゲン SVG アイコン表示） → Step3 → Step4 の順で進めること
- 「同意して始める」で `/scan` へ遷移し、再訪問時はオンボーディングをスキップすること

### 4. スキャン画面検証（scan 機能変更時）
- カメラが起動すること
- 撮影ボタンでプレビュー表示に遷移すること
- 結果カードに免責メッセージ（⚠️ 購入前にラベルの実物も確認ください）が常時表示されること

### 5. 履歴画面検証（history 変更時）
- 「自分のスキャン」タブに履歴カードが表示されること
- 「みんなのスキャン」タブが正常に切り替わること
- 編集モーダル・削除確認ダイアログが動作すること

### 6. 設定画面検証（settings 変更時）
- アレルゲン一覧が SVG アイコン付きで表示されること
- トグルの ON/OFF が反映されること

### 7. ネットワークエラー確認
```
mcp__chrome-devtools__list_network_requests
```
- 4xx / 5xx エラーがないこと（意図的なもの以外）
- 認証エラー（401/403）が発生していないこと

### 8. コンソールエラー確認
```
mcp__chrome-devtools__list_console_messages
```
- ERROR レベルのメッセージがないこと
- 未処理の Promise rejection がないこと

## Chrome チェックを省略できない条件

以下の変更を含む場合は Chrome 実機チェックなしでのコミット禁止:

| 変更カテゴリ | 理由 |
|---|---|
| 認証ガード・ミドルウェア変更 | 401/403/リダイレクトループは型チェックで検出不可 |
| ルーティング・リダイレクト変更 | 遷移先ミスは実ブラウザでしか確認できない |
| API クライアント変更 | レスポンス処理エラー（204の `.json()` 等）は実行時にのみ発生 |
| UI コンポーネント変更 | CSS・レンダリングバグは型チェック対象外 |
| Cookie / JWT / セッション変更 | 認証状態の破損はブラウザ実行でのみ確認できる |
| i18n キー変更 | 翻訳漏れは画面で確認する |

---

## セキュリティ制約（遵守必須）

- **リダイレクトクエリパラメータ禁止**: `?redirect=` `?callbackUrl=` `?returnTo=` 等で遷移先を外部から制御しない（CWE-601 オープンリダイレクト）
- 認証後の遷移先は常に `/scan` 固定
- 詳細: `anti_patterns.md` #18
