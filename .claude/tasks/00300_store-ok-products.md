## 背景・目的

購入場所登録 + 専用マップ（位置情報機能）でデータが貯まると、
「いまいる店舗で、自分のアレルギー設定的に OK な商品」を提案できる。
公開スキャン（is_public=true）の集合知を活かした、このアプリ独自の価値になる機能。

## Requirements

- 店舗（または現在地近傍）を指定すると、その店舗で過去にスキャンされた商品のうち、
  ユーザーの現在のアレルギー設定で `ok` 判定になる商品を一覧表示する
- 判定はリクエストユーザーの設定で動的に導出する（`deriveProductJudgment` を再利用）
- **公開履歴（is_public=true）に紐づく商品のみ**を対象にする（products/others と同じプライバシー方針）
- 商品カードにはサムネイル・商品名・最終スキャン日時を表示
- `expires_at` 切れの商品は「情報が古い可能性」タグを付ける（既存 is_expired と同じ扱い）

## 設計メモ

- 前提: 位置情報機能（00310 相当・購入場所登録 + マップ）が先行
  - `scan_histories.location` の lat/lng を独立カラム化 + インデックスが必要になった段階で実施
- API 案: `GET /products/ok-at-store?store_name=...` または `?lat=&lng=&radius=`
  - 実装は products 集約（store ごとの商品） × deriveProductJudgment フィルタ
- 店舗名の表記ゆれ（セブンイレブン渋谷店 / セブン-イレブン渋谷店）対策として
  Google Places の place_id を location に保存しておくと将来の店舗キー統一が楽
- マップのピン詳細パネルからこの一覧への導線を設ける

## 注意点（安全設計）

- 「OK 商品」はあくまで参考情報。一覧画面にも必ず免責
  「⚠️ 購入前にラベルの実物も必ずご確認ください」を常時表示する（anti_patterns.md #15）
- 他ユーザーのスキャン時点と現在で原材料が変わっている可能性があるため、
  `expires_at` 切れの表示は省略しない
- リコール・原材料変更リスクを考慮し、最終スキャンが古い商品（例: 180日超）は表示しない案も検討
