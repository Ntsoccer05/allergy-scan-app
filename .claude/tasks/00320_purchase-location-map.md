## 背景・目的

スキャンした商品の購入場所を登録し、アプリ専用マップにピンとして蓄積する。
履歴ページで「現在地から近い順」の検索も可能にする。
00300（店舗OK商品提案）の前提となる位置データ基盤。

## Requirements

### フェーズ A: 購入場所登録の完成（2〜4人日）

- スキャン時に GPS 座標を自動保存（既存実装）。デフォルトの場所表示は現在地の住所
  - 逆ジオコーディング: **国土地理院 逆ジオコーダ API**（無料・日本特化・出典表記が条件）
- 施設内の場合は施設名を選択して登録できる
  - 施設名解決は **Google Places Nearby を「場所を登録」操作時のみ呼ぶ**
    （スキャン毎に呼ばない = ランニングコストの支配項。同一地点の直近呼び出しはキャッシュ）
  - 将来の店舗キー統一のため place_id も location JSONB に保存する
- 結果カード・編集モーダルから場所の修正が可能

### フェーズ B: 専用マップページ（4〜7人日）

- 地図ライブラリ: **MapLibre GL JS**（無料）+ タイル: OpenFreeMap または MapTiler Free
  - ⚠️ 地図実装は `MapView` ラッパーコンポーネント（props: center / pins / onPinClick）に
    閉じ込める。Google Maps への将来差し替え・React Native 移行を1〜3人日に抑えるため
- 自分の履歴のピン表示・クラスタリング・ピンタップ→履歴詳細
- 公開スキャンのピン表示（is_public=true のもののみ。プライバシー方針は products/others と同一）

### フェーズ C: 近い順検索（1〜2人日 / みんな横断は +3〜5人日）

- 履歴ページに「現在地から近い順」ソートを追加
- 自分の履歴のみ: 取得済みデータの距離ソートで開始
- みんなのスキャン横断で必要になったら: scan_histories の lat/lng カラム抽出
  （NULL 許容追加・ダウンタイムなし）+ earthdistance/PostGIS + GiST インデックス

## ランニングコスト想定（2026-06 時点・¥155/$）

- 〜100 MAU: 全 API 無料枠内 → ¥0/月
- 1,000 MAU（場所登録率30%）: Places 超過分 約¥5,000/月。登録率10%なら ¥0
- 地図タイル・逆ジオ: ¥0（OpenFreeMap / 国土地理院）
- 3,000 MAU 規模で Places 約¥6.4万/月 → キャッシュ強化 or 代替（Foursquare 等）を再検討

## 注意点

- 位置情報はプライバシー要配慮。公開スキャンのピンは店舗粒度に丸める（自宅でのスキャン座標を
  そのまま公開しない — 施設名が確定したもののみ公開ピン化する等）
- GPS 取得失敗時は従来どおり場所なしでスキャン継続（既存 R14）
- 国土地理院 API は試験公開のため、本番前に利用規約・レート制限を確認する
