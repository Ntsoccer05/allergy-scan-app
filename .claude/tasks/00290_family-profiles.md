## 背景・目的

アレルギー子育て層がコアユーザー。現在ユーザー1人につきアレルギー設定は1セットだが、
「自分用」「子供用」など家族メンバーごとに設定を分け、スキャン時に切り替えられるようにする。

## Requirements

- ユーザーは複数のプロファイル（名前 + アレルギー設定セット）を作成できる
- スキャン画面でアクティブプロファイルを切り替えられる（例: 上部にプロファイルチップ）
- スキャン判定・履歴の再評価はアクティブプロファイルのアレルギー設定で行う
- 既存ユーザーの `users.allergies` は「デフォルトプロファイル」として移行する
- 履歴にはどのプロファイルでスキャンしたかを記録する（snapshot 同様、判定の文脈を残す）

## 設計メモ

- DB: `user_profiles` テーブル新設（id / user_id FK / name / allergies JSONB / is_default / display_order）
  - `users.allergies` は後方互換のためデフォルトプロファイルと同期 or 段階的に廃止
  - `scan_histories.profile_id` を NULL 許容で追加（既存行は NULL = デフォルト）
- API: `GET/POST/PUT/DELETE /users/me/profiles`、スキャン系 API に `profile_id`（省略時デフォルト）
- プロンプト生成（buildGeminiPrompt）はプロファイルの有効アレルギーで行う
- フロント: アクティブプロファイルをクライアント状態 + サーバー保存（最後に使ったプロファイル）
- 判定導出の集約点 `deriveProductJudgment(allergens, allergies)` は引数がプロファイルの
  allergies になるだけで再利用可能

## 注意点

- アレルギー設定は要配慮個人情報。プロファイル名に実名を推奨しない UI 文言にする
- 複数プロファイル同時判定（「家族全員で食べられるか」）は将来拡張として検討
  （results をプロファイル別にまとめて表示する案）
- 無料プランのプロファイル数上限（例: 2）→ プレミアム差別化要素になりうる
