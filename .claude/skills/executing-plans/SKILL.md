# 計画を実行する

## 概要

計画をロードし、批判的にレビューし、すべてのタスクを実行し、サブエージェントでレビューして完了する。

**コアプリンシパル:** 計画を批判的にレビューし、全タスクを実行し、サブエージェントレビューを経て完了する。

**開始時に宣言:** 「executing-plans スキルを使ってこの計画を実装します。」

**前提:** ブランチの作成・切り替えはユーザーが事前に行っておく。

**注意:** サブエージェントが利用可能な場合は、このスキルの代わりに `subagent-driven-development` を使用すること。サブエージェントを使うと品質が大幅に向上する。

## プロセス

### Step 1: 計画をロードしてレビューする

1. 計画ファイルを読む
2. 批判的にレビュー — 計画に関する質問や懸念を特定する
3. 懸念がある場合: 開始前にユーザーに提起する
4. 懸念がない場合: TodoWrite を作成して進む

### Step 2: タスクを実行する

各タスクについて:
1. `in_progress` としてマークする
2. 各ステップを正確に従う（計画には一口サイズのステップがある）
3. 指定された通りに検証を実行する（`test-driven-development` スキルに従う）
4. `completed` としてマークする

**各タスク完了後にコミット:**
```bash
git add <変更したファイル>
git commit -m "feat: <タスク内容>"
```

### Step 3: タスク間レビュー（各タスク完了後）

各タスク完了後にコードレビューを実施する（`requesting-code-review` スキルを使用）:

```bash
BASE_SHA=$(git rev-parse HEAD~1)
HEAD_SHA=$(git rev-parse HEAD)
```

- サブエージェントを派遣してレビュー
- **Critical / Important な問題:** 即座に修正してから次のタスクへ
- **Minor な問題:** 記録して後で対応

### Step 4: 全タスク完了後の仕上げ

すべてのタスクが完了して検証されたら:
- 宣言: 「finishing-a-development-branch スキルを使ってこの作業を完了します。」
- **REQUIRED SUB-SKILL:** `finishing-a-development-branch` を使用
  - テスト全体検証
  - ドキュメント更新
  - 最終コードレビュー（サブエージェント）
  - プッシュ/PR or 保持の選択

## いつ止まって助けを求めるか

**以下の場合はすぐに実行を停止する:**
- ブロッカーに当たった（依存関係が見つからない、テストが失敗、指示が不明確）
- 計画に開始を妨げる重大なギャップがある
- 指示が理解できない
- 検証が繰り返し失敗する

**推測するのではなく、確認を求める。**

## 記憶すること
- まず計画を批判的にレビューする
- 計画のステップに正確に従う
- 検証をスキップしない
- 各タスク後にコミットしてサブエージェントレビューを行う
- ブロックされたら止まる、推測しない

## 統合

**必要なワークフロースキル:**
- **`writing-plans`** — このスキルが実行する計画を作成
- **`requesting-code-review`** — タスク間レビュー
- **`finishing-a-development-branch`** — すべてのタスク後の仕上げ（ドキュメント更新・最終レビュー・PR）
