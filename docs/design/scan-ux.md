# スキャンUX設計

## 基本方針
- タップ撮影（手動シャッター・プレビュー確認あり）またはギャラリーからファイルアップロード
- シャッター音なし（動画フレームキャプチャを使用）
- フラッシュライトなし（コンビニ・スーパーでの迷惑回避）
- 暗い場合は「明るい場所に移動してください」ガイド表示のみ
- ⚠️ 免責注意文（「購入前にラベルの実物も必ずご確認ください」）はカメラオーバーレイ内に常時表示（スクロール不要）

---

## スキャン状態管理

> 型定義・定数は `.claude/rules/patterns.md` パターン5 を参照。

## 状態遷移

```
idle（カメラ映像ライブ表示 + 撮影ボタン）
  ↓ タップ撮影
preview（プレビュー確認）
  ├─ 撮り直す → idle
  ↓ 確定
processing（S3 PUT → API 判定）
  ↓              ↓
result        error
              └─ api_error → idle（ユーザーが撮り直し）
```

---

## スキャンフロー

### タップ撮影（カメラ）

```
カメラ常時起動（ライブ表示）
      ↓ ユーザーが撮影ボタンをタップ
フレームキャプチャ（無音・動画フレーム取得）
      ↓
プレビュー表示（撮り直す / 確定する）
      ↓ 確定
S3 Presigned URL へ PUT → POST /scan/ocr
      ↓
結果カードがスライドイン
```

### ファイルアップロード（ギャラリー）

```
「画像から解析」ボタンをタップ → OSファイル選択ダイアログ
      ↓ ファイル選択
S3 Presigned URL へ PUT → POST /scan/ocr
      ↓
結果カードがスライドイン
```

- OCR エンドポイントを通るため日次スキャンカウントに加算される
- `useScan.uploadAndScanImage(file: File)` で実装（`useCamera` を経由しない）

## ガイドメッセージ

| 状態 | メッセージ |
|---|---|
| idle | バーコードまたは原材料欄をカメラに向けて撮影してください |
| preview | この画像でよろしいですか？ |
| processing | 確認中... |
| error（incomplete） | ラベル全体が映るように撮り直してください |
| error（api_error） | 通信エラーが発生しました。再度お試しください |

## キャッシュ設計

> 詳細（TTL・層の責務分担）は `.claude/rules/architecture.md` キャッシュ層の責務分担を参照。

- Layer 1：クライアントキャッシュ（TTL: 2時間）— 同一セッション内の重複スキャン防止
- Layer 2：NestJSメモリキャッシュ（TTL: 60秒）— Lambda再起動でリセットされるため短期のみ
- Layer 3：DBのexpires_at（TTL: 30〜180日）— scan_count連動で延長
