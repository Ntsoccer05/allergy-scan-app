# OCR安全設計

## 根本思想
「OCRが間違える前提で設計する」

判定不明・読み取り不完全は必ず安全側（警告）に倒す。
「たぶん大丈夫」を出さない。

---

## 2層構造

### Layer 1：送信前に画像品質を担保（端末側）

- ブレ・暗さ・ピントを自動チェック
- 品質不足はdetectingで自動待機（ユーザー操作不要）
- 3フレーム連続でOKになった瞬間だけキャプチャ

### Layer 2：Geminiへの指示（サーバー側）

有効なアレルゲンのみをプロンプトに渡す（allergen_componentsテーブルから動的生成）。
トークン節約と判定精度向上を両立する。

---

## Geminiプロンプト設計

```
ユーザーが設定しているアレルゲン：[卵, 乳]（例）

【検出対象成分】（allergen_componentsテーブルから動的生成）
・乳、牛乳、生乳、乳成分、乳等を主要原料とする食品
・カゼイン、カゼインNa（⚠️risk_level:high）
・ホエイ、ホエイパウダー、ホエー、乳清（⚠️risk_level:high）
・バター、チーズ、アイスクリーム、生クリーム、練乳
・卵、玉子、たまご、エッグ、egg
・卵黄、卵白、albumin
・オボムコイド（⚠️risk_level:high・加熱でも残る）
・マヨネーズ（複合原材料）、リゾチーム

【含む表記パターン（必ず検出すること）】
・「（乳成分を含む）」「（一部に乳成分を含む）」
・「（卵を含む）」「（一部に卵を含む）」
・「原材料の一部に〜を含む」
・「〜由来」（例：乳由来、卵由来）

【コンタミ注意喚起（containsと明確に区別すること）】
・「本製品工場では〜を含む製品を製造しています」
・「〜を使用した設備で製造しています」
→ これは detection_type: 'may_contain' として返す

【検出対象外（誤検出に注意）】
・乳化剤（乳由来でない場合が多い）
・乳酸菌・乳酸（乳アレルギーと無関係）
・カカオバター（乳ではない・植物性）
・卵殻カルシウム（抗原性ほぼなし）

前処理ルール：
・全角半角・スペース・記号の揺れを正規化してから解析すること
・「乳 等 を 主 要 原 料 と す る 食 品」のような分かち書きも正規化すること
・不明な文字は「？」で返すこと
・不明な場合は不明と返すこと（推測しない）
・テキストが途切れている場合は incomplete:true を返すこと
・価格が表示されていれば合わせて返すこと

返答はJSON形式のみ（前置き・説明文は不要）：
{
  "raw_text": "読み取った原材料テキスト全文（正規化前の原文）",
  "confidence": "high / medium / low",
  "results": [
    {
      "allergen": "乳",
      "judgment": "含む / 一部含む / なし / 判定不能",
      "detection_type": "contains / partial / may_contain",
      "detected": ["カゼイン", "ホエイ"],
      "risk_level": "high / medium / low",
      "reason": "カゼイン（乳由来タンパク・risk_level:high）を検出"
    }
  ],
  "highlights": [
    { "text": "カゼイン", "judgment": "ng" },
    { "text": "一部に乳成分を含む", "judgment": "partial" },
    { "text": "本製品工場では卵を含む製品を製造", "judgment": "may_contain" }
  ],
  "incomplete": false,
  "price": 298,
  "price_with_tax": 321,
  "price_confidence": "high / low / null"
}
```

highlightsはraw_text内でユーザーに視覚的にハイライト表示する文字列の一覧。
- `judgment: "ng"` → 🔴
- `judgment: "partial"` → 🟡
- `judgment: "may_contain"` → 🟠（コンタミ・注意喚起）

---

## confidence別の処理

```
high      → 通常判定表示
medium    → 判定表示 + 「⚠️ 一部読み取りにくい箇所があります。ラベルも確認してください」
low       → 「もう少し近づけて再スキャンしてください」→ detecting継続
判定不能   → 同上
incomplete:true → 「ラベル全体が映るように離してください」→ detecting継続
```

---

## 安全設計のルール（絶対に変えてはいけない）

1. **raw_textを必ず画面に表示する**
   ユーザー自身が「アプリが読んだ文字」を確認できる状態にする

2. **「購入前にラベルの実物も必ずご確認ください」を全判定で常時表示する**

3. **NG判定時は追加で警告を表示する**
   「このアプリの判定は参考情報です。アナフィラキシーのリスクがある方は必ず実物ラベルでご確認ください」

4. **疑わしい成分は🔴にする。OKの確信が持てないものは🟡にする**
   「たぶん大丈夫」を出さない

5. **incomplete:trueが返ってきたら必ず再スキャンを促す**
   部分的な原材料情報で判定しない

---

## アレルゲン判定の2段階分類

| 分類 | 判定基準 | 表示 |
|---|---|---|
| 含む | 原材料に直接表記 or 派生成分含む | 🔴 NG |
| 一部含む | 「一部に〜を含む」or コンタミ注意書き | 🟡 注意 |
| なし | 該当成分なし | ✅ OK |

## OCR精度向上のための実装ポイント

### 画像前処理
- フレームを5fpsに間引いて品質チェック（バッテリー節約）
- 3フレーム連続OKで初めてキャプチャ（1フレームだけOKでは撮らない）
- ピントは画面中央に自動フォーカス強制指定

### 画像送信
- 画像はS3 Presigned URL経由でアップロード（Lambda直接送信禁止・6MB制限回避）
- NestJSにはS3キーのみ渡す

### プロンプト最適化
- 有効なアレルゲンのみプロンプトに渡す（無効なものは含めない）
- 除外リストも渡して誤検出を防ぐ
- 「不明なら不明と返せ」を明示する
