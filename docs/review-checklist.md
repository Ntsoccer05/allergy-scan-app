# PRレビューチェックリスト

本ファイルは Claude Code が `verification-before-completion` および `requesting-code-review` スキル実行時に参照するチェックリスト。

---

## 共通チェック項目

### 1. 不要コード
- 未使用のインポート（import文）が残っていないか
- 未使用の変数・型定義・関数が残っていないか
- 不要になったコード（コメントアウトされたコード等）が残っていないか

### 2. 型安全性
- `any` 型を使用していないか（`unknown` または適切な型定義を使用すること）
- 型定義に `interface` ではなく `type` を使用しているか（`extends` による拡張やクラス実装の契約定義が必要な場合のみ `interface` を許容）
- `as` による型アサーションを使用していないか（型ガード `instanceof`, `typeof` やカスタム型述語関数を使用すること）
- ジェネリック型が適切に使用されているか

### 3. 命名規則
- 1文字の変数名（`i`, `j`, `k`, `x`, `y`, `z`, `e`, `s` など）を使用していないか（イテレータ変数も2文字以上: `idx`, `rowIdx`）
- 汎用的すぎる変数名（`tmp`, `data`）を使用していないか
- **フロントエンド**: コンポーネントファイルはPascalCase、カスタムフックは `useHoge.ts`、機能ディレクトリはcamelCase
- **バックエンド**: ファイル名はkebab-case、クラス名はPascalCase、ディレクトリ名はkebab-case

### 4. マジックナンバー
- 数値リテラルがコード中にハードコードされていないか
- 意味のある定数名で定義されているか

### 5. 重複コード
- 同一・類似ロジックがコピペされていないか
- 共通関数・共通コンポーネントに抽出すべき処理がないか
- 同じJSXパターンが複数箇所にないか

### 6. エラーハンドリング
- エラーを再スロー（throw）する際に日本語エラーメッセージを含む新しいErrorインスタンスを作成しているか
  - ❌ `throw error;`
  - ✅ `throw new Error('日本語メッセージ', { cause: error });`
- 外部API呼び出し・S3操作・Gemini APIにtry-catchが適切に使用されているか

### 7. ESLint規約
- `eslint-disable` を使用していないか（やむを得ない場合のみ行単位で使用し、理由をコメントに明記）
- ファイル全体の `eslint-disable` は禁止
- `console.log` を使用していないか（`console.debug`, `console.warn`, `console.error`, `console.info` は許可）

### 8. コメント規約
- 複雑なロジックに背景や意図を説明するコメントがあるか
- 個人的メモや感想的なコメントが残っていないか
- 一時的な対応の場合、実装背景と今後の対応方針がコメントとして残されているか

## バックエンド固有

### 9. アーキテクチャ（レイヤー責務分離）
- Controller → Service → Repository のレイヤー構造を遵守しているか
- **Controller**: リクエスト受取・バリデーション・レスポンス整形のみ。ビジネスロジックの実装は禁止
- **Service**: ビジネスロジック実装。`$queryRaw` の直接使用は Repository に移譲
- **Repository**: CRUD・検索・集計のみ
- DTO / Entity の役割が混同されていないか

### 10. NestJSルーティング順序
- Controllerで静的ルートが動的ルートより前に定義されているか
  - ✅ `@Get('/digest')` → `@Get('/:id')`
  - ❌ `@Get('/:id')` → `@Get('/digest')`

### 11. Swagger/DTO
- オプショナルなプロパティに `@ApiPropertyOptional` を使用しているか
- DTOのバリデーションデコレータが適切に設定されているか

### 12. マイグレーション
- ファイル名がkebab-caseか
- クラス名がPascalCase + タイムスタンプか
- タイムスタンプが未来日時になっていないか
- カラム追加は `NULL` 許容 or `DEFAULT` 付きで行っているか（ダウンタイムなし）

### 13. N+1問題
- ループ内で1件ずつDBクエリを発行していないか
- バッチ取得に変更すべき箇所がないか

### 14. ロガー
- NestJSのLoggerでは `logger.info()` ではなく `logger.log()` を使用しているか
- `console.log` を使用していないか

## フロントエンド固有

### 15. API通信
- データ取得は TanStack Query（`useQuery` / `useInfiniteQuery`）を使用しているか
- データ変更は `useMutation` を使用しているか
- Hook を経由せず fetch を直接呼んでいないか

### 16. React Hooks
- `useEffect` の依存配列が適切か
- 空の `useEffect`（何も実行しないもの）が存在しないか
- レンダリングごとに再定義する必要のない関数・型はコンポーネント外で定義されているか
- 不要な再レンダリングを避けるため `memo`, `useMemo`, `useCallback` が適切に使用されているか

### 17. インポート
- 絶対パス（`@/` プレフィックス）を使用しているか
- インポート順序がルールに従っているか（builtin → external → internal → sibling/parent）

### 18. Nullish値の処理
- オプショナルチェーン `?.` を使用して安全にアクセスしているか
- Nullish結合演算子 `??` を使用してデフォルト値を設定しているか

### 19. スタイル
- カラーのハードコードを避け、shadcn/ui のテーマトークンまたは Tailwind config の定義済みカラーを使用しているか
- TailwindCSSのインラインユーティリティクラスを使用しているか（`@apply` は共通化が必要な場合のみ）

### 20. ファイル配置（Atomic Design）
- atoms: 最小UI部品のみ・ビジネスロジックなし
- molecules: atoms の組み合わせ
- organisms: 独立した機能ブロック・直接 fetch 禁止（Hook 経由）
- templates: レイアウト枠のみ・データ取得禁止
- 共通利用 → `components/atoms|molecules|organisms/`
- ページ固有 → `app/[page]/components/`

## インフラ固有

### 21. Terraform
- Terraformファイルの変更がある場合、`terraform fmt` が実行されているか
- 命名規則が snake_case に統一されているか
- 変数に型が明示的に定義されているか

## 横断的チェック

### 22. 環境変数・インフラ整合性
- 環境変数の追加・変更がある場合、対応するTerraform設定の更新があるか

### 23. フロントエンド/バックエンド整合性
- 同じ概念の定数値がフロントとバックエンドで一致しているか
- APIのリクエスト/レスポンスの型が一致しているか

### 24. セキュリティ
- Presigned URL の有効期限が用途別に正しく設定されているか（OCR PUT: 5分 / 自分の履歴GET: 1時間 / 公開サムネイルGET: 24時間）
- 認証・認可チェックが漏れていないか

### 25. 既存パターンとの統一
- 既存の実装パターンと異なるアプローチを取っている箇所はないか
- 新しいパターンを導入する場合、既存コードとの一貫性を考慮しているか

## このプロジェクト固有

### 26. OCR安全設計（命に関わる）
- `confidence: low` の場合に判定結果を返していないか（再スキャン誘導のみ）
- `incomplete: true` の場合に即エラー返却しているか（部分判定禁止）
- `judgment === '判定不能'` を「なし」として扱っていないか
- スキャン結果画面に免責UI（「⚠️ 購入前にラベルの実物も確認ください」）が常時表示されているか
- NG判定時に「このアプリの判定は参考情報です」が表示されているか

### 27. i18n
- UIテキストがコンポーネントにハードコードされていないか（`t('キー名')` 経由を徹底）
  - ❌ `<p>購入前にラベルの実物も確認ください</p>`
  - ✅ `<p>{t('scan.result.caution')}</p>`
- ja/en 両方の locales ファイルにキーが存在するか

### 28. スキャン回数制限
- OCR・バーコード・画像アップロード（Presigned URL発行）後に `user_daily_scans` が +1 されているか
- `not_food_label: true` の場合はカウントしていないか
- サムネイル変更・メモ・店舗名編集はカウント対象外になっているか
- 上限超過時に `429` を返しているか

### 29. 認証・認可
- 管理者エンドポイント（`/admin/*`）に `AdminGuard` が漏れなく適用されているか
- `@Public()` デコレータが `/public/*` 以外に使われていないか
- Supabase JWT の検証をスキップしている箇所がないか
- `app_metadata.role` の確認が AdminGuard で正しく行われているか

### 30. Atomic Design 遵守
- atoms がビジネスロジックを持っていないか
- organisms が直接 fetch/API 呼び出しをしていないか（Hook 経由を徹底）
- templates がデータ取得をしていないか（Pages に委譲）
- LoadingOverlay は共通コンポーネント（`atoms/LoadingOverlay`）を使用しているか

### 31. 画像・ストレージ
- OCR画像は `scans/{user_id}/{YYYY-MM}/{uuid}.jpg` に保存されているか
- サムネイルは `thumbnails/{user_id}/{history_id}.jpg` の固定キーか
- サムネイル変更時に同一キーで上書きしているか（旧ファイルが自動削除される）
- 画像はアップロード前にクライアント側で圧縮されているか（OCR: 1920px/85% / サムネイル: 600px/80%）
